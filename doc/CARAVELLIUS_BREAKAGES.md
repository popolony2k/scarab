# Breakages for Caravellius

What Scarab's master-plan work changes for Caravellius, the game built on Scarab. Nothing
here has been sent to Caravellius yet. It is told when this plan is released, as agreed
with the owner.

This file lives on `master_plan` only. It is removed when this plan is merged to `main`,
after Caravellius has been told what changed.

**Status:** `merged` = on `master_plan`, unreleased. `pending` = on the working branch, not
yet merged.

## Merged to master_plan

| 1 | **V1 (sunlight BREAKAGES 24, 46)** `camera_move_*` / `view_move_camera_*` stop exactly on the map's edges. Up/left now stop on the map's real far edge, `-ceil(view size / zoom - map size)` pixels from the origin (shown as a positive `camera_get_position()`), with a partial last step when less than a step is left. Before (sunlight v0.38.0) they could scroll up to about one tile *past* that edge, in whole steps. Down/right now come back to exactly `0`; before, they stopped one step short (with Scarab's default 1 px step: at `1`, not `0` - read from v0.38.0's code, not measured). Measured on `resources/tilemap/test.tmx` with a 7 px step: zoom 3.8125, 1240x900 view: far edge 314/403 (was 315/427), back to 0 (was 7). Zoom 1.0, 300x200 view: 340/440 (was 371/469). | Any game that scrolls with these calls. Caravellius scrolls down with `camera_move_down()` (`src/camera.lua`, per the example in Scarab's own `camera_move_up` doc - not re-checked in Caravellius' repo), so its scroll now ends at camera y `0`, not `1`. Any code that compares the camera against a fixed end value, or that works out a tile or a wave from the camera by dividing by the step, may see different numbers. | Check `src/camera.lua` and anything that reads `camera_get_position()` against a fixed end value or divides it by the step. Re-run the intro/demo timing that depends on where the scroll ends. |
| 2 | **P4 (sunlight BREAKAGES 50, "I1")** Semi-transparent drawing is no longer darker than authored. Before, every frame was drawn into a render target whose own alpha dropped under each semi-transparent draw, and that target was then blended over a black window, so anything semi-transparent came out darker (eg. `test.tmx`'s 0.65/0.69 cloud layers: a pixel at 167 173 175 instead of Tiled's 242 250 253). Opaque drawing is unchanged. | Anything semi-transparent: layers below full opacity, object and sprite opacity, soft sprite edges, text edges, and the screen fade. No code change is needed. | Recheck any colour, alpha or fade value that was tuned by eye to make up for the darkening, and any screenshot or golden-image comparison. Compare semi-transparent layers, the HUD/text and the screen fade with how they were authored. |
| 3 | **V2 (sunlight BREAKAGES 35)** At a non-integer zoom, which includes Scarab's default 3.8125, tiles, image layers and sprites are now drawn at whole screen pixels (rounded half-up). The thin seams of background colour between adjacent tiles, and the 1 px gap at some camera positions, are gone. Each tile's and sprite's exact screen pixel can move by up to about 1 px compared with before. The scroll limit at the map's far edge changed too: that's entry 1. | Every game at a non-integer zoom. If Caravellius runs at Scarab's default zoom, or any other non-integer zoom (not checked in Caravellius' repo), all of its drawing is affected, by at most about a pixel. Collisions, positions and every other game logic value are unchanged: only where things are drawn moved. | Nothing in code. Any screenshot or golden-image comparison needs new reference images. Any art or HUD element tuned by eye to hide a seam can lose that workaround. |
| 4 | **V3 (sunlight BREAKAGES 41)** A layer's opacity, as `tilemap_get_layer`/`tilemap_set_layer` (and their `_by_name` forms) exchange it, is now a real 0..255, 255 = opaque, clamped when written. Before (sunlight v0.38.0, measured on the published Scarab v0.1.25): an opaque layer read **256**, layers authored at 0.69/0.65 both read 255 (now 176/166), writing 128 read back 382, writing a layer's own values back changed them (256 became 254), and nothing was clamped. Writing 255 used to store opacity 0.0, an invisible layer, though it read back as 255. | Any script that reads or writes a layer's opacity. sunlight noted that Caravellius' `src/core/presentation.lua` reads and writes a layer's opacity back to hide a layer: it now keeps the value instead of storing -1.0, with no visible change since the layer is hidden (sunlight's reading, not re-checked here). | Check any script that compares an opacity against 256 or 255, computes one around the old numbers, or relied on writing 255 to hide a layer. Use `visible = false` to hide a layer. |
| 5 | **V4 (sunlight BREAKAGES 2)** `KEY_MENU` is now **5**, raylib's own value (Android's menu button), and sunlight translates keys to raylib by name. Before (sunlight v0.38.0, measured on the published Scarab v0.1.25), `KEY_MENU` was **82**, the same number as `KEY_R`, and sunlight passed the number straight to raylib. So `input_is_key_down( KEY_MENU )` fired on the **R** key, and a Lua table keyed by key value treated the two as one key. Now `KEY_MENU` never fires on a desktop keyboard. | Any script that uses `KEY_MENU`, or stored the number 82 for it. sunlight's BREAKAGES says Caravellius doesn't use `KEY_MENU` (sunlight's reading, not re-checked here). | Check for `KEY_MENU`, and for a saved binding or hard-coded `82` meant as the menu key. A game that wanted the R key should use `KEY_R`. |
| 6 | **C6 (sunlight BREAKAGES 52, "I3")** Fonts by handle. New Lua functions: `load_font( path ) -> font \| nil, message` (load a file once), `release_font( font )`, `register_font( family, font, bold, italic )` / `unregister_font( font \| family, bold, italic )` (the map's Tiled text objects; without a registered font they draw `??????`), and an optional last `font` argument on `draw_text` and `measure_text`. **`set_font` changed:** it now takes a path (load and select, as before), a font handle, or `nil` (the built-in font), and on failure returns **`nil, "message"`** where it returned `false`. | Caravellius' `Text.set_font` (`src/core/text.lua`, called from `src/main.lua` with `caravellius8x8_bold.fnt`) keeps working through the path form; only a check for exactly `false` would see `nil` now (not re-checked in Caravellius' repo). Any map text object needs `register_font`. | Optional: load each font once with `load_font` and pass the handle to `set_font`, `draw_text` (several fonts on screen without switching) and `register_font`, instead of reloading by path. Check any code that compares `set_font`'s result with `false`. |
| 7 | **V5 (sunlight BREAKAGES 8, 11, 17; and O3)** Tiled **text**, **tile** (`OT_TILE`) and **point** objects in a map are now drawn; up to sunlight v0.38.0 all three were invisible. A text object draws only with a font registered for its family (`register_font`, C6), else `??????`. Separately (O3), shape objects' outlines now scale with zoom. | Caravellius' maps have no text, tile or point objects today (`corsair.tmx`, `cover.tmx`, read from the local checkout `22bbaaf`), so nothing new appears. But `corsair.tmx`'s 3 trigger markers (`SubBossIntervalStart`, `SubBossIntervalEnd`, `CephalonPosition`) are **rectangle** objects on a layer without `visible="0"`: sunlight drew rectangles before and still does, so they are probably on screen in the game, now with zoom-scaled outlines. | Check whether the 3 trigger rectangles are visible in the game; if they are, hide their layer (`visible="0"`, or `tilemap_set_layer`) or give them no colour. Any marker added later should be a rectangle on a hidden layer, never a text, tile or point object, which would now be drawn. Register a font for every text-object family a map uses. |
| 8 | **V6 (sunlight BREAKAGES 18-20, 53)** Tiled objects with a **rotation** are drawn turned clockwise about their stored point: rectangles, polylines, polygons, ellipses, tile objects and text objects. Before, the rotation was ignored. Also (I4, entry 53): a map whose embedded tileset image path contains `..` (eg. `../../sprites/x.png`) now loads, where `tilemap_load_map` used to refuse the whole map. | Caravellius' maps have no rotated objects and no `..` image paths today (`corsair.tmx`, `cover.tmx`, checked in the local checkout), so nothing changes on screen. | Nothing today. A rotated object added to a map later will now draw turned, as Tiled shows it. Maps may now share one image across folders with `..` paths. |
| 9 | **D3** Every Lua function that can fail returns **`nil, "message"`**, never a Lua error and never a silent no-op; one with nothing else to return returns `true`. Arguments are checked strictly: a wrong type, a missing argument, a **fractional number where an integer is expected** (`3.5`; `3.0` is fine), a value out of range (`0..1` for `screen_fade`/`sound_set_volume`/collision insets, `0..255` colours, `0..65535` for every `sp_*` parameter, which used to wrap silently) or not one of its constants (a misspelt `KEY_*` name is `nil`) all fail and change nothing. `sprite_acquire` returns `nil, "message"` for an unknown or full pool (it returned **`0`**); functions that returned `false` return `nil, msg`; getters of an invalid sprite handle return `nil, msg` (`sprite_get_visible`/`_world_space` returned `false`); a second `sound_load` of a loaded id is refused (it was silently ignored); `camera_move_up/left` with no map return `nil, msg`. | **Caravellius must change 23 places in 18 files**: every `if handle == 0 then` right after `sprite_acquire` (all four `bullets/*`, `core/` twin, weapon x2, options x2, pickups, storyboard, and the enemies satellite x2, octopus, galileo, alien, cephalon x3, cylinder, nomad, ufo, venusiansubboss) never fires now, so an exhausted pool would carry a `nil` handle on. Otherwise checked on the local checkout `22bbaaf`: acceptance PASS and the reference state fingerprint (`hash=33897632`), the only error met being `sprite_remove_from_layer` on a sprite not on the layer (it returned `false`, same falsiness). Not covered by a headless run: code behind real input. | Replace `handle == 0` with `not handle`. Search for `== false` / `== 0` checks of these functions' results. Check that fades and volume ramps stay inside `0..1` (an overshoot is now refused, not clamped) and that every `sprite_set_pos`/`camera_set_position` value is a whole number (Caravellius already truncates). Optionally read the new messages (`local ok, err = ...`) when debugging. |
| 10 | **V7 (sunlight BREAKAGES 36)** Shape objects (rectangle, ellipse, polyline, polygon, point) and text objects in a map now follow their layer's opacity; before, they were always drawn at their own colour's alpha. A Tiled object's own `opacity` custom property (0 to 1) now overrides its layer's opacity, for tile, shape and text objects; a value outside 0..1 is ignored with a warning. | Caravellius' maps have no object layer below opacity 1.0 and no `opacity` property (`corsair.tmx`, `cover.tmx`, local checkout), so nothing changes on screen, the 3 trigger rectangles of entry 7 included. | Nothing today. A semi-transparent object layer, or an `opacity` property, added to a map later now dims its shapes and text as Tiled shows them. |
| 11 | **V8a (Scarab's own bug)** Every sprite was drawn twice per frame: once in its layer by sunlight, then again on top of the whole frame by Scarab (`SpritePool::UpdateAll`), which ignored layer visibility, layer order and view layer masks. Now a sprite is drawn once, in its layer's place: hiding a layer (`tilemap_set_layer(id, false, ...)`, or `visible="0"` in the map) hides its sprites, a view's layer mask hides them in that view, and a sprite sits under the map layers above it instead of over everything. Animation pace is unchanged. | Every game with sprites. Caravellius' acceptance and state fingerprint are unchanged (local checkout `22bbaaf`). It hides one layer: `core/presentation.lua:319` (and `debug/storyboard_stage.lua:57`) hide `LAYER_PLAYER_SHIP` during the intro storyboard to blank the cover art, on the assumption that the player ship never spawns there; a sprite on that layer would now be hidden too. Any sprite on a layer below a map layer that covers it is now drawn under it (headless runs can't show this). | Check the cover/intro by eye. Check, by eye in a real window, that every sprite still shows where it should: one meant to fly over map art must be on a layer above that art. Any code that hid a layer expecting its sprites to stay visible must hide only the art instead. |
| 12 | **V8 (sunlight BREAKAGES 39)** A sprite added to a layer while no map is loaded is now drawn right away; before, it stayed invisible until a map loaded. With no map, layer ids are grouping keys drawn in ascending id order, and a view's layer mask hides them by id. Sprites added with no map are now also released at shutdown. | Caravellius never adds a sprite before its map: a temporary trace counted zero `sprite_add_to_layer` calls with no map loaded over the acceptance and state fingerprint runs (local checkout `22bbaaf`), so nothing changes on screen. Not covered: code reached only by player input. | Nothing today. A sprite added before its stage's map loads would now show over an empty background until the map appears; keep deferring sprite setup until after the map loads. A title screen or menu can now draw sprites without any map. |
