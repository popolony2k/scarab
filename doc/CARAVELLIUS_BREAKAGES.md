# Breakages for Caravellius

What Scarab's master-plan work changes for Caravellius, the game built on Scarab. Nothing
here has been sent to Caravellius yet. It is told when this plan is released, as agreed
with the owner.

This file lives on `master_plan` only. It is removed when this plan is merged to `main`,
after Caravellius has been told what changed.

**Status:** `merged` = on `master_plan`, unreleased. `pending` = on the working branch, not
yet merged.

| 1 | **V1 (sunlight BREAKAGES 24, 46)** `camera_move_*` / `view_move_camera_*` stop exactly on the map's edges. Before (sunlight v0.38.0) they could scroll up to about one tile *past* that edge, in whole steps. | 5 | **V4 (sunlight BREAKAGES 2)** `KEY_MENU` is now **5**, raylib's own value (Android's menu button), and sunlight translates keys to raylib by name. | 9 | **D3** Every Lua function that can fail returns **`nil, "message"`**, never a Lua error and never a silent no-op; one with nothing else to return returns `true`. Arguments are checked strictly: a wrong type, a missing argument, a **fractional number where an integer is expected** (`3.5`; `3.0` is fine), a value out of range (`0..1` for `screen_fade`/`sound_set_volume`/collision insets, `0..255` colours, `0..65535` for every `sp_*` parameter, which used to wrap silently) or not one of its constants (a misspelt `KEY_*` name is `nil`) all fail and change nothing. `sprite_acquire` returns `nil, "message"` for an unknown or full pool (it returned **`0`**); functions that returned `false` return `nil, msg`; getters of an invalid sprite handle return `nil, msg` (`sprite_get_visible`/`_world_space` returned `false`); a second `sound_load` of a loaded id is refused (it was silently ignored); `camera_move_up/left` with no map return `nil, msg`. | **Caravellius must change 23 places in 18 files**: every `if handle == 0 then` right after `sprite_acquire` (all four `bullets/*`, `core/` twin, weapon x2, options x2, pickups, storyboard, and the enemies satellite x2, octopus, galileo, alien, cephalon x3, cylinder, nomad, ufo, venusiansubboss) never fires now, so an exhausted pool would carry a `nil` handle on. Optionally read the new messages (`local ok, err = ...`) when debugging. |
| 10 | **V7 (sunlight BREAKAGES 36)** Shape objects (rectangle, ellipse, polyline, polygon, point) and text objects in a map now follow their layer's opacity; before, they were always drawn at their own colour's alpha. A Tiled object's own `opacity` custom property (0 to 1) now overrides its layer's opacity, for tile, shape and text objects; a value outside 0..1 is ignored with a warning. | Caravellius' maps have no object layer below opacity 1.0 and no `opacity` property (`corsair.tmx`, `cover.tmx`, local checkout), so nothing changes on screen, the 3 trigger rectangles of entry 7 included. | Nothing today. A semi-transparent object layer, or an `opacity` property, added to a map later now dims its shapes and text as Tiled shows them. |

Now a sprite is drawn once, in its layer's place: hiding a layer (`tilemap_set_layer(id, false, ...)`, or `visible="0"` in the map) hides its sprites, a view's layer mask hides them in that view, and a sprite sits under the map layers above it instead of over everything. Animation pace is unchanged. | Every game with sprites. Caravellius' acceptance and state fingerprint are unchanged (local checkout `22bbaaf`). Any sprite on a layer below a map layer that covers it is now drawn under it (headless runs can't show this). | Check the cover/intro by eye. Check, by eye in a real window, that every sprite still shows where it should: one meant to fly over map art must be on a layer above that art. Any code that hid a layer expecting its sprites to stay visible must hide only the art instead. |
| 12 | **V8 (sunlight BREAKAGES 39)** A sprite added to a layer while no map is loaded is now drawn right away; before, it stayed invisible until a map loaded. With no map, layer ids are grouping keys drawn in ascending id order, and a view's layer mask hides them by id. Sprites added with no map are now also released at shutdown. | Caravellius never adds a sprite before its map: a temporary trace counted zero `sprite_add_to_layer` calls with no map loaded over the acceptance and state fingerprint runs (local checkout `22bbaaf`), so nothing changes on screen. | 13 | **V9 (sunlight BREAKAGES 47, 55)** `tilemap_unload_map` unloads every sprite on a layer: its textures are released, it has no active sequence (`sprite_get_active_sequence` returns `-1`), it is on no layer and its collider is taken out, so it never collides while unloaded. To use it again after the next map loads, configure it, set its sequence and add it to a layer again; it then collides once per frame. The collision rules are kept. Up to the published v0.1.25 the same steps crashed (exit 139) on the next frame. Loading a map over a loaded one does not unload sprites. | Caravellius never calls `tilemap_unload_map` (local checkout `22bbaaf`): it loads each stage's map over the previous one, which keeps sprites as before. Nothing changes. | Nothing today. If a later change unloads a map, set every sprite that must survive it up again afterwards. |
| 14 | **V10 (sunlight BREAKAGES 40)** `tilemap_load_map` over a loaded map frees the old map (its tile textures, tile animations and resources); up to the published v0.1.25 every such switch leaked the whole previous map (measured headless, CPU side only: about 30 KB per load; in a window also its GPU textures). Sprites stay on their layers, as before. The new map is read first: if it fails to load, the call returns `nil, "cannot load map ..."` and the loaded map stays loaded; before, no map was left. | Caravellius switches stages with `tilemap_load_map` and no unload (`core/bootstrap.lua`), so it leaked every previous stage and now doesn't, with nothing to change. Its failure path (`if not tilemap_load_map(...)` prints and returns `false`) works with `nil`; a stage map that fails to load now leaves the previous stage's map on screen instead of none. | Nothing to change. Optionally check that a failed stage load (which refuses the stage) is fine with the previous stage's map still loaded. |
| 15 | **V11 (sunlight BREAKAGES 4, 56)** Sprite-vs-tile collisions and tile lookups now work, in **map space**. `collision_set_tile_handler` never ran in any Scarab release (Scarab called the Lua handler with the wrong argument count), and sunlight tested only the tile under a sprite's top-left corner, shifted by the viewport origin. Now each frame checks every tile with a Tiled collision shape that a sprite overlaps, and calls the handler once per tile, with the tile's map rectangle; touching edges don't count. `tilemap_to_tile_matrix(x, y)` takes a map position (before, the viewport origin and the camera were added first), and `tilemap_get_tile`'s x/y/w/h are map pixels. | Caravellius has no tile with a collision shape (`corsair-tileset.tsx`, checked) and calls none of these functions (local checkout `22bbaaf`), so nothing changes. | Nothing today. If a later map uses collision tiles: a handler that blocks movement must undo the frame's movement once per frame, and all of it (a sprite in a corner gets two calls; a diagonal is two steps). |
| 16 | **V12 (sunlight BREAKAGES 45, 57)** Layer tint, group layers and image-layer opacity. A tile object stretched to a box of another size now takes its object layer's Tiled `tintcolor` (it used to be drawn untinted). New Lua functions `tilemap_get_layer_tint` / `tilemap_set_layer_tint` (and `_by_name`) read and change a layer's tint at runtime (r, g, b, a 0..255; the alpha is kept but ignored for drawing). Group layers are now drawn as Tiled draws them: a group's opacity and tint multiply into everything inside it (shapes and text take only its opacity); before, groups were ignored. Image layers now apply their own opacity; before, they were always drawn opaque. | Caravellius' maps have no tint, no group layer, and one image layer (`cover.tmx`'s "Cover Image") with no opacity set, so nothing changes on screen (local checkout `22bbaaf`). | Nothing today. A tint, a group or an image-layer opacity added to a map later now shows as Tiled shows it. A layer's tint can be changed from Lua (eg. a damage flash, a day/night colour). |
| 17 | **P7 (sunlight BREAKAGES 58)** A layer's opacity, as `tilemap_get_layer` / `tilemap_set_layer` (and their `_by_name` forms) exchange it, is now a **number from 0 to 1** (1 = opaque), Tiled's own unit, read exactly as authored (a layer at 0.69 reads `0.69`) and written back exactly; it was an integer 0..255 (entry 4). `tilemap_set_layer` refuses an opacity outside 0..1, or not a number, with `nil, "message"` and leaves the layer as it was (before, any integer was clamped). Before, every read-and-write-back moved an authored 0.5 to 0.502. | Caravellius' `core/presentation.lua` (lines 316-319) reads a layer's opacity and passes the same value back to hide the layer: it keeps working (acceptance and state fingerprint unchanged, local checkout `22bbaaf`). Any code that compares an opacity with 255 or 256, computes one in 0..255, or writes a literal like 128 is now wrong. | Search for `tilemap_set_layer` / `tilemap_get_layer` calls that use numbers in 0..255 and convert them to 0..1 (divide by 255); a literal 255 meaning "opaque" becomes 1. |
| 18 | **P8 (sunlight BREAKAGES 59, "I10")** New, nothing breaks: a sprite has its own **opacity** and **tint**. `sprite_set_opacity( h, 0..1 )` / `sprite_get_opacity( h )` (1 = opaque, the default; read back exactly) and `sprite_set_tint( h, r, g, b[, a] )` / `sprite_get_tint( h )` (0..255, white = no tint; `a` kept but not used for drawing). The tint's RGB multiplies into whatever frame the sprite draws, in every sequence and view; two sprites on the same texture keep their own values; a sprite does not take its layer's opacity or tint. `sprite_release` resets both, so a recycled handle starts opaque and untinted. A sprite that never sets them draws exactly as before. | Caravellius calls none of them, so nothing changes (acceptance PASS and state fingerprint `hash=33897632` unchanged, local checkout `22bbaaf`). | Nothing to change. Optional: fades, hit flashes and team colours on a sprite without extra textures (eg. a red tint for a few frames when the ship is hit, instead of a separate flash sequence). |
| 19 | **V13 (sunlight BREAKAGES 44, 60, "I11")** A Tiled tile animation now runs **by time**, as Tiled shows it: the frame shown is the time since `tilemap_load_map`, modulo the animation's cycle. Every cell and tile object of a tile is in step, and a tile that isn't drawn (off screen, on a hidden layer, masked out of a view) no longer pauses: scrolled back on screen it shows the frame for the time now. Before, an animation advanced only while drawn, showed its first frame twice each cycle, and held a frame whose duration isn't a whole number of frames until the next draw. An all-0 ms animation shows its first frame. New Lua functions `tilemap_get_tile_frame(row, col, layerId)` / `tilemap_get_object_tile_frame(name)` return the gid drawn now. | Caravellius has no animated tile in its maps (checked by sunlight and here) and calls neither function, so nothing changes (acceptance PASS, state fingerprint `hash=33897632`, local checkout `22bbaaf`). | Nothing today. A map with animated tiles now animates at its Tiled durations, in step everywhere; game logic can read a tile's current frame (eg. a spike trap that hurts only while its "up" frame shows). |
